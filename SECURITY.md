# Security policy

The Trindle website is a small project looked after by one person, not a company with a security team. This page says what to expect.

## Supported versions

Only the latest version is supported. There is no older branch and no backporting.

| Version | Supported |
|---|---|
| 1.0.0 | yes |

## Reporting a problem

**Please do not put the details of a security problem in a public issue.** A public report tells everyone before a fix exists.

Use GitHub's private vulnerability reporting: open the Security tab of this repository and choose **Report a vulnerability**. If that does not work for you, write to hello@trindle.org and say it is a security report.

Please include which page it is on, what you did, what you expected and what happened.

## What to expect

You will get a reply, usually within a week, though this is one person and it can take longer. A fix goes into the next version of the site, and you will be told when it is live. There is no money to offer for reports, only thanks.

## What counts

The site is plain files with two small scripts and no server code. Useful reports include a script that does something it should not, a link to the wrong place, or a page that loads something from another company. The Trindle desktop itself has its own policy when its code is public.
